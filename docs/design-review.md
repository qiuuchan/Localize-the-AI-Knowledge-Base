## §3 · 反模式自检(4 处自违规)

两份文档均设了"反模式清单"自查,但**实际违反自身条款**。这是设计文档最严重的可信度问题。

### 3.1 自违规 #1:Emoji 作为状态图标(`🔴` `🟡`)

**涉及文件**:
- `design.md:651` `🔴 离线模式 — AI 暂时不可用,您可以查看历史对话`
- `design.md:669` `🟡 已切换到网络搜索 — 回答可能基于公开信息`
- `MASTER.md:838-841` (ASCII 草图) 同样的 emoji 用作"在线/离线/降级"标识

**违反条款**:
- MASTER §7.4 行 493: "**禁止用 emoji 作为结构性图标。所有图标必须是 Lucide SVG**"
- design §10.1 第 5 项: "❌ 使用 emoji 作为结构性图标 → 禁止"

**修正方案**(任选一):
- (A) 状态条文字去掉 emoji,纯文字 + Lucide 图标(如 `WifiOff`/`Wifi`)
- (B) 在反模式清单加例外 "**状态条文字前缀**允许 emoji 作语义指示符,仅此一处;其它结构性图标仍用 Lucide"
- (C) 文档内部承认存在不一致,把所有 emoji 替换为 Lucide

**推荐 (A)**:保持反模式原则单纯,emoji 仅在 emoji-native UI(emoji-only 平台)使用,KB-AI 不在此列。

### 3.2 自违规 #2:Glassmorphism 实际启用

**矛盾点**:
- `design.md:876-877`: "打开起始:opacity: 0, scale: 0.95, **backdrop-filter: blur(0)**"; "打开结束:opacity: 1, scale: 1, **backdrop-filter: blur(4px)**"
- `design.md:886`: "无 backdrop-filter 时不降级,opacity 即可"
- **但同一份文档** `§10.1 第 3 项`自评:`❌ Glassmorphism(玻璃拟态) | ✅ 未使用 | 无 backdrop-filter blur,无半透明层叠`

**结论**:**设计原则与具体动画细节直接矛盾**。

**修正方案**(任选一):
- (A) 接受 backdrop-filter,承认与"经典商务黑灰"基调**有轻微冲突**(可争辩:模态弹出时短暂 blur 是合理微动效,不构成"玻璃拟态"风格);修订 §10.1 第 3 项自评为 ⚠️ "部分使用(仅模态弹出瞬间)"
- (B) 取消 backdrop-filter 细节,模态只做 opacity + scale;自评保留 ✅

**推荐 (B)**:保持设计原则纯净;若是觉得模态弹出"太平",可加 ring 阴影增强聚焦感而不是 backdrop blur。

### 3.3 自违规 #3:模型名出现在 UI(违反 brief §12.4 #4)

**涉及文件**:`design.md:1142` "当前模型:显示 'Qwen3-Plus(由后端自动选择)'"

**违反决策**:
- `frontend-design-brief.md §12.1 #4`: **"模型路由 = 后端静默调,无 UI"**
- 这意味着前端**不显示模型选择按钮、不显示当前模型名**(降级黄条除外)

**修正方案**:
- 删除 `design.md §8.4` 中"AI 设置(只读) → 当前模型"行
- 保留"AI 由系统自动选择,您无需手动切换"说明文字即可
- MASTER.md 不出现这条(无违规)

**推荐**:删除模型名展示,只保留"系统自动选择"的说明文字。

### 3.4 自违规 #4:W 占位符颜色对比度不足(2.7:1)

**涉及**:`MASTER.md:277` 标注 `foreground-tertiary #9CA3AF` 对比度 2.7:1 ⚠ (仅用于非关键文字),`MASTER.md:1133` 占位符 2.7:1 ⚠ 同注

**自我标注合规**(因注了仅用于非关键),不构成违规。但要继续验证:
- #9CA3AF 作为 placeholder 在 input 上,实际是"用户开始输入前的提示"——非关键但用户最终交互会触碰
- **WCAG 2.1 1.4.3**(大文本 18px+ 或 14pt+ bold)需要 3:1,**不达**
- 建议:补一行"或使用 #6B7280 增强对比度到 5.7:1",或注明"严禁放在 < 18px 关键提示位置"

## §6 · 维护性建议(3 个选项,你选)

### 6.1 选项 A:**合并为单一 MASTER**(推荐)

- 把 design.md 视觉叙事 + 文案语气 + 设计自评 作为新增章节并入 MASTER.md
- 单一真相源;18 处冲突彻底消除;维护只动一个文件
- 缺点:MASTER 变 ~2500 行,部分章节(如 §11 附录)会更长

### 6.2 选项 B:**严格分层(MASTER 为真相源,design 仅做叙事)**

- MASTER.md 是 token / 规则 / 组件 / 触达规则的唯一来源
- design.md 只做"叙事"(隐喻 / 文案 / 文化),不再写具体 hex / pixel;遇到具体值时引用 `→ MASTER §X.Y`
- 冲突天然消除;缺点:design.md 需要大删减

### 6.3 选项 C:**维持两份,设主次**

- MASTER.md 是真相源
- design.md 在文件头标注"⚠ 副;以 MASTER 为准"
- 任何冲突以 MASTER 为准
- 缺点:还是会有人读 design 错过 MASTER 的更新

**我的推荐:选项 A(合并)**——你只做一个项目,设计文档是给工程实施看的;分散两份会增加维护摩擦。

## 任务完成率持平的归因(重要,先看再说结论)

22 条工具选择通过中,**20 条同时通过关键词口径;2 条"未过"是关键词字面口径的假阴性,不是系统错误**:

- 「储值增长百分比」「毛利率」两条:工具链完整正确(kb_search → calculator 都调了),计算结果正确(22.37 / 37.5),但答案用数字+文字表述("22.37(保留两位小数)")没带 `%` 字符 —— 判定关键词是字面子串 `%`。
- **改进项(记 v2.1.1 候选)**:评测口径应把 `%` 类符号关键词放宽为语义判定(LLM-as-judge 或归一化"%/百分之/percent"),否则完成率被口径压低约 8.7pt。真实能力 ≈ 22/23。

## 唯一失败用例(诚实归因)

「企业微信服务流程分几个阶段?每个阶段平均要 3 天,总共多少天?」—— 期望 kb_search + calculator,实际只调了 kb_search,4×3 的**隐性乘法**被模型心算(答案给对了 12 天,但绕过了工具)。

- 与 v2.0 的失败同根因(隐性计算),但**换了一条用例**:v2.0 失败的 3 条(增长/间隔/翻倍)本轮全部通过 —— 提示词强化有效但未根治;
- 边界特征:失败用例的乘法最"平凡"(个位数×个位数),模型倾向跳过;显式指令类("用计算器算出")全部通过;
- **v2.1.1 候选方向**:对"总共/合计/间隔/翻倍"类意图做规则预判强制注入 calculator,或 few-shot 加平凡乘法反例。

## 流式链路的实战验证

本轮评测全部经 v2.1.0 流式 Agent 链路(`/api/agent/chat` stream=True,`answer_delta`/`answer_reset` 事件):23 条无一条流式中断或错乱,usage 计量照常落账(每任务 5,478 tokens,与 v2.0 的 5,685 同量级)—— 流式改造零回归。

## 结论

1. **提示词强化(禁止心算)有效**:multi_step_calc 3/5 → 4/5,web_fallback 3/4 → 4/4,总通过率 86.96% → 95.65%。
2. **任务完成率持平是口径问题不是能力问题**:2 条假阴性(字面 `%`),v2.1.1 应修评测口径。
3. 采样方差仍显著(单条用例轮次间不稳定),稳定结论取区间:**工具选择准确率 ≈ 87%-100%**(三轮:87 / 87 / 95.65)。
4. 流式链路零回归;keyword-only 降级下全链路可用(单腿故障可用性再次验证)。

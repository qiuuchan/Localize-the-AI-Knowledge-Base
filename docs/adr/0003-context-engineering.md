## Context

v2.2 之前的会话上下文策略是**双轨数量截断**:

- `/api/chat`:`history_limit`(默认 50 条消息)尾部截断 + `format_chunks_only(max_context_chars=6000)` 字符预算(只约束检索上下文,不约束历史);
- `/api/agent/chat`:`history_limit` 同样按条数截断。

问题:

1. **条数 ≠ token 数**:50 条"您好"和 50 条长文档问答的 token 消耗差两个数量级,条数上限既可能撑爆 context,也可能浪费窗口;
2. **无记忆**:历史截断 = 信息丢失,用户问"刚才那个数字"时上下文里已经没有;
3. 面试视角(本周期主线):腾讯 JD 原文列「Long-term Memory」,`docs/REVIEW-GUIDE.md:30` 自认"无滚动摘要/向量记忆"短板。

候选方案:

- **A. 引入向量记忆(Mem0/Zep/自建向量库存会话)**
- **B. 滚动摘要:token 预算 + 超阈值压缩 + 摘要落库参与后续上下文** ← 选定
- **C. 纯滑动窗口(只截尾,无摘要)**

## Decision

**B:启发式 token 估算(零新依赖)作预算计量,超阈值时「最近消息保留 + 更早历史压成摘要」,摘要落 `sessions.summary` 参与后续轮次上下文。**

- 预算只约束**历史会话**部分;检索上下文继续走 `format_chunks_only` 字符预算,LLM 输出继续走 `max_tokens`,三者正交;
- 摘要默认**启发式**(确定性、零成本、可测试、失败不可能);LLM 摘要作为可选增强,失败静默回退启发式(项目「降级不阻断」DNA);
- 计量口径:启发式估算(CJK≈1 token/字符,ASCII≈1 token/4 字符,×1.2 保守系数),**与 cost 计量的关系**:cost 的单一真相源是 API 真实 usage(`llm._log_token_usage`),预算估算不替代它——预算回答"调用前放多少",cost 回答"调用后花多少"。

## 权衡(为什么不做 A / 不选 C)

### 1. 向量记忆是单用户场景的过度工程

向量记忆的价值在跨会话/多用户/语料持续膨胀时的「语义召回」:用户的 100 轮会话若互不相干,向量检索召回的也是"看起来像"的历史,反而引入噪音;本项目单用户、会话内上下文强相关,摘要 + 最近消息已覆盖 95% 的「之前提到的 X」类追问。**先做确定性方案,把向量记忆留到 Mem0/Zep 类产品真正需要的时刻。**

### 2. 摘要 vs 滑动窗口:信息可恢复性不同

滑动窗口(方案 C)实现最简单,但被截掉的历史**永久丢失**;摘要把信息从"逐字"降维到"要点",代价是精度损失。选择摘要的理由:

- 餐饮经营对话中,用户追问「上一个问题里提到的数字」的频率远高于「逐字复述」;
- 摘要是**一次压缩、多次复用**:压缩成本均摊到后续 N 轮,而非每轮重读全量历史;
- 摘要落库后与 `history_limit` 解耦——历史可以无限长,预算恒定。

### 3. 为什么不引入 tiktoken / 用 API 精确计量

- tiktoken 是 OpenAI 分词器,Qwen 用**自己的** tokenizer,引入只是"更精确的近似",不是真相;
- API 侧有 `usage` 字段,但那是**事后**数字,无法在"调用前"决定取舍;
- 启发式 ×1.2 保守系数 + 预算默认 6000 远低于 Qwen 3.x 的 128K 窗口,**高估的代价是可忽略的窗口浪费,低估的代价是请求 400**——方向上宁可高估。

### 4. 何时该上 Mem0/Zep(演进路径)

- 会话数 > 1000 且跨会话引用频繁(「我上个月问的那个方案」);
- 需要跨用户隔离记忆(多租户,见 FAQ#10 口径);
- 需要语义去重/知识沉淀(把会话答案沉淀为知识库文档)。

届时 `condense_history()` 的输入/输出契约不变——它只是"历史 → (保留历史, 摘要)"的纯函数,替换内部实现即可,调用方零改动。

## 代价与缓解

| 代价 | 缓解 |
|---|---|
| 启发式摘要信息丢失(措辞/细节) | 保留最近消息(预算 55%)保证近期精度;摘要只覆盖早期轮次 |
| 摘要生成时机:仅在超预算那一轮触发一次,不每轮重写 | 摘要合并为追加式(既有摘要 + 新摘要),截断到预算内 |
| 估算与真实 token 有偏差 | 保守系数 1.2;预算默认 6000 ≪ 128K 窗口,边界安全 |
| 单测需要构造"超预算"数据 | 预算走 env `HISTORY_TOKEN_BUDGET` 可注入,测试直接设小值 |

## Open Questions(不阻塞)

1. **LLM 摘要增强**:后续可在 `condense_history` 外包一层 LLM 摘要器(独立 `summary_prompt` + `max_tokens≈300`),失败回退启发式;golden-agent 复测确认不引入噪音后再默认开启。
2. **摘要是否参与检索**:当前摘要只进 LLM 上下文,不进 Qdrant 检索;若跨会话引用成为高频,可把摘要写入知识库(池外)。

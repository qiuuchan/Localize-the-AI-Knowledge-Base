## 0. 你需要准备什么

| 物品 | 来源 | 备注 |
|---|---|---|
| **新 MacBook Air** | Apple Store / 经销商 | macOS 13+(Ventura)+ Apple Silicon 强烈推荐 |
| **旧 Win U盘** | 你手头 1TB 移动 SSD | 数据全在这上面,要保留 |
| **第 2 块盘**(强烈推荐) | 任何 USB 硬盘 / 网盘 / Mac 本地盘 | 用来中转数据,新 Mac 格式化旧 U盘前必须先备份 |
| **稳定的 WiFi** | 你家 / 办公室 | Docker 镜像 + Python 依赖下载 |
| **你的 Apple ID + 密码** | 你 | 登录 App Store / iCloud |
| **2 小时无打扰** | — | 一次做完,别被打断 |

⚠️ **不要在没有第 2 块盘的情况下开始**(详见 §1.2 数据迁移)。

## 2. 阶段 A:Mac 系统准备(0:00 - 1:15,~75 分钟)

### A.1 首次开机(0:00 - 0:10)

新 Mac 第一次开机,跟着系统引导走:
1. **语言**:选 `简体中文`
2. **键盘**:选 `简体中文 - 拼音`
3. **网络**:连 WiFi
4. **数据传输**:跳过(Mac 和 Win 不能直接互导)
5. **Apple ID**:登录你的 Apple ID
6. **iCloud**:可以开(主要看 Drive / 钥匙串)
7. **FileVault**:建议开启(U盘数据 + Mac 本地数据都加密)

### A.2 系统设置(0:10 - 0:20)

**设置 → 通用 → 登录项**:暂时不装第三方 App
**设置 → 隐私与安全性 → 完全磁盘访问权限**:先不管(后面用时再说)
**设置 → 通知**:关掉垃圾通知
**设置 → 聚焦 → 快捷键**:可改可不改
**设置 → 共享**:把电脑名改成 "MacBook Air (maintainer)" 之类

### A.3 安装 Xcode Command Line Tools(0:20 - 0:30)

**打开 Terminal.app**(Launchpad → 实用工具 → 终端)

```bash
xcode-select --install
```

会弹窗,点"安装"+"同意"。约 3-5 分钟(下载 ~500MB)。

**验证**:
```bash
gcc --version
# 应输出 Apple clang version 15.x 或类似
```

### A.4 安装 Homebrew(0:30 - 0:45)

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

按提示输入密码,会装 ~1 分钟。**完成后会提示你跑两行命令**把它加到 PATH(就是下面这种):

```bash
# Apple Silicon Mac(默认)
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
```

**验证**:
```bash
brew --version
# 应输出 Homebrew 4.x
```

### A.5 安装工具链(0:45 - 1:00)

**Docker Desktop**(最大,先装):
```bash
brew install --cask docker
```

装完后启动 Docker Desktop(`/Applications/Docker.app`),首次会要求输入系统密码授权 + 同意订阅协议(选 Personal 免费)。等 Docker 图标从"动画"变成"静止"就 OK 了。

**PowerShell 7+**(KB-AI 编排脚本语言):
```bash
brew install --cask powershell
```

**Python 3.12**(KB-AI 后端依赖):
```bash
brew install python@3.12
```

**git + 常用工具**(通常 Mac 自带,但确认下):
```bash
git --version    # 应 ≥ 2.39
which pwsh       # 应 /opt/homebrew/bin/pwsh
which python3.12 # 应 /opt/homebrew/bin/python3.12
which docker     # 应 /usr/local/bin/docker 或 /opt/homebrew/bin/docker
```

### A.6 安装 Kimi Code(1:00 - 1:15)

**打开浏览器** → 访问 [Kimi Code 下载页](https://kimi.com/code) → 下载 Mac 版 dmg → 双击安装 → 拖到 Applications

**打开 Kimi Code** → 首次会要求授权(辅助功能 / 屏幕录制 / 自动化)— **全选"允许"**。

**新建会话** → 在工作目录选你的 KB-AI 项目根(等 §B 迁移完再选)。

## 3. 阶段 B:U盘数据迁移(1:15 - 2:15,~60 分钟)

⚠️ **这是最容易出错、最容易丢数据的环节。**仔细看,别跳步。

### B.1 现状确认

**插旧 Win U盘到新 Mac**。

打开 Terminal:
```bash
diskutil list
```

会看到类似:
```
/dev/disk0 (internal):    ← Mac 自带盘(别动!)
/dev/disk1 (synthesized):
/dev/disk2 (external, physical):   ← 你的 U盘!
   #:                       TYPE NAME                    SIZE       IDENTIFIER
   0:      GUID_partition_scheme                        *1.0 TB     disk2
   1:           Microsoft Basic Data AIAssistant         1.0 TB     disk2s1
```

**重要确认**:
- `disk2` 是 U盘
- 名字是 `AIAssistant`(卷标)
- 文件系统是 `Microsoft Basic Data`(= NTFS)

**验证 Mac 能读**:
```bash
ls /Volumes/AIAssistant/
# 应看到 start.bat, stop.bat, precheck.bat, package.bat,
# QUICKSTART.md, docker-compose.yml, backend/, data/, scripts/ ...
```

**`ls` 看得到** = OK。如果看不到,先看 Finder 里有没有挂载。

### B.2 数据备份(必须,无第 2 块盘就别继续)

**方案 A:Mac 本地盘(有 ≥ 200GB 空间时推荐)**
```bash
mkdir -p ~/Desktop/KB-AI-Backup-Temp
cp -R /Volumes/AIAssistant/. ~/Desktop/KB-AI-Backup-Temp/
```

**方案 B:另一块 USB 移动硬盘**
```bash
# 假设第 2 块盘叫 BackupDrive
cp -R /Volumes/AIAssistant/. /Volumes/BackupDrive/KB-AI-Backup-Temp/
```

**验证复制完整**:
```bash
# 文件数应一致
find /Volumes/AIAssistant/ -type f | wc -l
find ~/Desktop/KB-AI-Backup-Temp/ -type f | wc -l
# 两个数字应相等(允许 1-2 差异,因为 Mac 临时文件)

# 大文件数应一致
du -sh /Volumes/AIAssistant/ ~/Desktop/KB-AI-Backup-Temp/
# 两个数应接近
```

**时间预估**:`cp -R` 1TB ≈ 30-60 分钟(取决于 USB 速度)。

### B.3 卸载 + 格式化 U盘

```bash
# 卸载(不会丢数据,只是 Mac 不再挂载)
diskutil unmountDisk /dev/disk2

# 格式化为 exFAT(跨 Win/Mac 互通)
diskutil eraseDisk ExFAT AIAssistant /dev/disk2
```

会清空 U盘全部内容。**确认已备份**!

**如果只想在 Mac 上用**(不放回 Win):用 APFS 性能更好:
```bash
diskutil eraseDisk APFS AIAssistant /dev/disk2
```

### B.4 数据回写 + 设卷标

```bash
# 重新挂载
diskutil mountDisk /dev/disk2

# 把数据拷回(从备份)
cp -R ~/Desktop/KB-AI-Backup-Temp/. /Volumes/AIAssistant/

# 设卷标(Mac 默认不会从 NTFS 卷标继承)
diskutil renameDisk /dev/disk2 AIAssistant
```

**验证卷标正确**(KB-AI 的 `get-usb-root.ps1` 靠这个定位):
```bash
mount | grep AIAssistant
# 应看到 "AIAssistant" 在挂载点路径里
```

**验证数据完整**:
```bash
ls /Volumes/AIAssistant/start.ps1    # v1.7.0 新增
ls /Volumes/AIAssistant/start.bat    # Win 入口
ls /Volumes/AIAssistant/QUICKSTART.md
```

### B.5 清掉 macOS 隐藏的"垃圾"文件(可选)

Mac 拷数据时可能会留 `.DS_Store` / `._xxx` 资源 fork。这些不影响 KB-AI 运行,但可以清理:

```bash
# 清掉隐藏资源 fork(可选)
find /Volumes/AIAssistant/ -name '._*' -delete
find /Volumes/AIAssistant/ -name '.DS_Store' -delete
```

### B.6 关键:数据迁移完整性验证

**打开 Finder,看 U盘根目录应该有**:
- `start.bat` + `stop.bat` + `precheck.bat` + `package.bat`(Win 入口,保留)
- `start.ps1` + `stop.ps1` + `precheck.ps1` + `package.ps1`(v1.7.0 PowerShell)
- `start.command` + `stop.command` + `package.sh`(v1.7.0 Mac 入口)
- `data/` + `vectors/` + `cache/`(知识库数据,**这是你最值钱的东西**)
- `backend/` + `scripts/` + `docs/` + `tests/`
- `docker-compose.yml` + `.env`(你填过 API key 的)+ `version`
- `tools/kb-ai-images.tar`(Docker 预置镜像,几 GB)

**如果 `data/` 看起来比 Win 上小很多**,立刻停止,回去看 §B.2 备份是否完整。

## 4. 阶段 C:KB-AI 启动(2:15 - 3:00,~45 分钟)

### C.1 放行 .command 文件

```bash
cd /Volumes/AIAssistant
chmod +x start.command stop.command package.sh
# 清掉可能的 Gatekeeper quarantine 标记
xattr -d com.apple.quarantine start.command stop.command 2>/dev/null
xattr -d com.apple.quarantine start.ps1 stop.ps1 precheck.ps1 package.ps1 2>/dev/null
```

### C.2 第一次跑预检

打开 Terminal(注意:从此开始 **所有命令都在 KB-AI U盘根目录** 下跑):

```bash
cd /Volumes/AIAssistant
pwsh -File precheck.ps1
```

**期望输出**(可能 1-2 项不通过是正常的,见下):
```
日志: /Volumes/AIAssistant/logs/precheck-YYYYMMDD-HHMMSS.log
  ============================================================
    KB-AI · 客户机预检  v1.7.0  平台=macOS
  ============================================================

    ✓ 虚拟化        启用(Apple Silicon (arm64) = native ARM virtualization)
    ✓ OS 版本      macOS 14.5
    ✓ 磁盘空间       446.7 GB(≥ 10 GB)
    ✓ 内存         16 GB(≥ 4 GB)
    ✓ SIP          enabled(Docker Desktop 推荐)
    ✓ Docker        /opt/homebrew/bin/docker
```

**如果有不通过项**:

| 失败项 | 修法 |
|---|---|
| ✗ 虚拟化 | Apple Silicon 永远 OK,Intel Mac 装 Docker Desktop 后会自动处理 |
| ✗ Docker 未安装 | `brew install --cask docker` + 启动 Docker.app + 等 30s |
| ⚠ SIP 关闭 | 保持 disabled 也行,只是会弹更多权限请求 |
| ✗ 内存不足 | KB-AI 5 容器需要 ≥ 4 GB,8GB MacBook Air 勉强,推荐 16GB+ |

### C.3 第一次启动 KB-AI(2:30 - 3:00,~30 分钟)

```bash
cd /Volumes/AIAssistant
pwsh -File start.ps1
```

**首次跑会做的事**:
1. 5 项预检(30 秒)
2. 启动 Docker Desktop(30 秒)
3. 检查 .env + 加载 Docker 镜像(1-2 分钟,**首次慢,会从 U盘 tar 文件 load 4 个镜像**)
4. 复制 HF 模型到 `~/.cache/huggingface`(30 秒)
5. 启动 5 容器(30-60 秒)
6. 等待 kb-ai-backend 健康(30-60 秒)
7. 打开浏览器到 `http://localhost:8000`

**期望最终输出**:
```
============================================================
   启动完成!
   KB-AI 前端:     http://localhost:8000
   ...
```

如果浏览器自动开了,看到 KB-AI 聊天界面 = **成功**!

### C.4 试一次对话

在浏览器里:
- 问:"你好,介绍下你自己"
- 看回答是否正常流式输出
- 试上传一个文件(图片 / PDF / Word)

### C.5 测试安全弹出

```bash
cd /Volumes/AIAssistant
pwsh -File stop.ps1
```

**期望**:
- 5 秒倒计时(可按 Enter 确认)
- 停后端 → 停容器 → 自动备份到 `~/KB-AI-Backup/`
- 弹"现在可以拔出"对话框(中文正常显示)
- 关闭对话框后,Finder 拖 U盘 图标到废纸篓

**如果弹窗失败**:走终端 fallback(直接显示文本),说明 osascript 权限未授。修法:`设置 → 隐私与安全性 → 自动化 → 终端 → 允许 osascript`。

## 7. 风险与兜底

### 7.1 数据丢失(最严重)

**预防**:
- §B.2 备份必须做,做完用 `wc -l` 验证文件数
- 不要用 `rm -rf` 或 `mv`,只用 `cp -R`
- 格式化 U盘前(`diskutil eraseDisk`)先 `ls /Volumes/AIAssistant/QUICKSTART.md` 确认数据还在

**如果已经丢了**:
- 旧 Win 机器还在的话,从 Win 那边重新拷一份
- 联系发盘人(maintainer),看有没有云备份

### 7.2 Mac 权限弹窗太多

新 Mac 首次跑脚本会弹:
- `终端 想访问 Files and Folders` → 允许
- `osascript 想控制 Docker` → 允许
- `终端 想访问 Full Disk Access` → 允许(系统设置 → 隐私与安全性)

**别把权限弹窗静音关掉**。第一次都点"允许",后面就不弹了。

### 7.3 Docker Desktop 启动失败

**症状**:`docker info` 报 daemon not running

**排查**:
```bash
# 看 Docker Desktop 日志
tail -50 ~/Library/Containers/com.docker.docker/Data/log/vm/console.log
# 或打开 Docker Desktop → Troubleshoot
```

**常见原因**:
- Mac 系统版本太旧(< macOS 11)→ 升级 macOS
- Apple Silicon Mac 没装 Rosetta → Docker Desktop 自动弹窗问要不要装,装
- 防火墙拦了 → 设置 → 网络 → 防火墙 → 允许 Docker

### 7.4 启动后 80 秒内 http://localhost:8000 没起来

**症状**:start.ps1 阶段 7 健康等待超时

**排查**:
```bash
# 看容器状态
docker ps -a
# 看 backend 日志
docker logs kb-ai-backend --tail 50
# 看健康检查
curl -v http://localhost:8000/api/health
```

**常见原因**:
- 首次冷启动慢:ARM 镜像解压比 x86 慢,等 2-3 分钟
- 后端进程卡住:`docker restart kb-ai-backend`
- 端口冲突:`lsof -i :8000` 看谁占着

### 7.5 聊天时偶发"database is locked"

**症状**:Dify worker 报错,聊天 500

**修法**:在 `/Volumes/AIAssistant/docker-compose.yml` 找 `dify-api` 和 `dify-worker` 的 volumes,把:
```yaml
- ./data:/app/api/storage
```
改为:
```yaml
- ./data:/app/api/storage:delegated
```

⚠️ 这是 §7.2 红线 #4(动 docker-compose.yml)的边界,改之前最好让 Mac Kimi Code 反馈给 maintainer。但这是只改 volume mount option 的小改,实际风险很低。

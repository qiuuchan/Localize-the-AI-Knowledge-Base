## 2. 文件级变更详情

### 2.1 Item A · `cost_log.jsonl` 日志轮转

**当前**:`E:/scripts/cost-alert.ps1`(v1.3.0 新建)只读不轮转;`cost_log.jsonl` 长期运行会无限增长。

**变更**:

1. **新建 `E:/scripts/lib/CostLog-Rotate.ps1`**,导出 2 个 PS 5.1 函数:
   - `Rotate-CostLog -Path <FileInfo> -ThresholdBytes <int>`:检测 size;超阈值则:
     1. 计算目标归档名:`cost_log.jsonl.<UTC-YYYY-MM>.gz`(若同月已存在则追加 `-N` 序号)
     2. 用 `[System.IO.Compression.GZipStream]` 压缩原文件到归档路径
     3. 截断原文件为空(用 `[System.IO.File]::WriteAllText($path, "", UTF8NoBom)`)
     4. 任何步骤异常 → Write-Warning + 保留原 .jsonl 不动 + 不抛异常(脚本继续)
   - `Get-MonthlyCostFromAllSources -DataDir <path> -YearMonth <string>`:扫描"当前 cost_log.jsonl + 同月所有 cost_log.jsonl.<YYYY-MM>[-N].gz 归档",按 `ts` 字段累加 input/output tokens 后返回 dict(供 B 共享)

2. **修改 `E:/scripts/cost-alert.ps1`**:
   - 顶部 dot-source:`. (Join-Path $PSScriptRoot 'lib/CostLog-Rotate.ps1')`
   - 在"读 + 累加"步骤之前插入 `Rotate-CostLog -Path (Join-Path $DataDir 'cost_log.jsonl') -ThresholdBytes 50MB`
   - 把累加逻辑改为调 `Get-MonthlyCostFromAllSources`(把硬编码当前文件改为扫描全部源)
   - **阈值常量** `$COST_LOG_ROTATE_BYTES = 50 * 1024 * 1024` 写在脚本顶部,带注释说明依据(U 盘项目单点故障,需保留)

3. **幂等性保证**:
   - 同月二次轮转 → 归档名追加 `-2` / `-3`(用 `Test-Path` 检测避免覆盖)
   - gzip 失败 → 保留原文件 + 跳过本次轮转(下次跑时再试)
   - 截断失败 → 归档已存在但原文件未截断 → 下次跑会再次 gzip 同一个原文件 → 用 `Test-Path` 检查归档是否存在避免重复归档

**接口契约**:
```
Rotate-CostLog
  输入: -Path <FileInfo> 目标文件
        -ThresholdBytes <int> 触发阈值
  输出: <void> 副作用:创建 .gz 归档 + 截断原文件
  异常: 全部 try/catch,Write-Warning 后继续(脚本不抛)

Get-MonthlyCostFromAllSources
  输入: -DataDir <string>
        -YearMonth <string> 形如 "2026-07"
  输出: @{input_tokens: int; output_tokens: int; sources: list[str]}
  异常: 同上
```

### 2.2 Item B · UTC 时区修正

**当前问题**:`E:/scripts/cost-alert.ps1` 用 `$entry.ts -like "$yearMonth*"` 字符串前缀比较做月度归类。`ts` 是 ISO8601 字符串(由 `_log_token_usage` 用 `datetime.now(timezone.utc).isoformat()` 生成,本身是 UTC),所以**理论上**当前代码正确。但风险在于:
- 若未来 `_log_token_usage` 改用本地时区(重构漂移),此比较会漏算
- 若 ISO8601 字符串带 `+08:00` 偏移(如某些三方 API),前缀比较会把 7/31 23:00(+08:00)归类到 8 月
- 若 ISO8601 字符串带 `Z` vs 不带 `Z`(whitespace/格式差异),字符串比较仍能工作但脆弱

**修正方案**:统一通过 `[DateTimeOffset]::Parse(...).ToUniversalTime()` 规范化后再比较。

**实现位置**:`E:/scripts/lib/CostLog-Rotate.ps1` 内新增函数:

```powershell
function Get-CanonicalUtcMonth {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory = $true)]
        [AllowEmptyString()]
        [string]$Timestamp
    )
    if ([string]::IsNullOrWhiteSpace($Timestamp)) {
        return "{0:yyyy-MM}" -f [DateTimeOffset]::UtcNow
    }
    try {
        $dto = [DateTimeOffset]::Parse($Timestamp).ToUniversalTime()
        return "{0:yyyy-MM}" -f $dto
    } catch {
        Write-Warning "Get-CanonicalUtcMonth: unparseable ts '$Timestamp', fallback to current UTC month"
        return "{0:yyyy-MM}" -f [DateTimeOffset]::UtcNow
    }
}
```

**修改 `E:/scripts/cost-alert.ps1`**:
- 把 `$entry.ts -like "$yearMonth*"` 替换为 `Get-CanonicalUtcMonth $entry.ts -eq $yearMonth`
- 在循环前预计算 `$yearMonth` 一次(避免每次循环都 `"{0:yyyy-MM}" -f [DateTimeOffset]::UtcNow`)

**向后兼容**:
- 当前 ts 始终是 UTC(`Z` 后缀),`DateTimeOffset::Parse` 仍返回正确 UTC → 行为不变
- 解析失败 fallback 用当前 UTC 月份 + Write-Warning → 不抛异常、不漏算

### 2.3 Item C · `safe_get_usage_tokens` 防御性解析

**当前问题**:`E:/backend/core/rag/llm.py:107-108` 与 `:170-171` 用裸 `int(u.get("input_tokens", u.get("prompt_tokens", 0)))`:
- 若 `u` 是字符串 `"invalid"`,`u.get(...)` 抛 `AttributeError`(str 没有 .get)
- 若 `u["input_tokens"]` 是 `"123"`(字符串数字),`int("123")` 工作;但若 `"abc"` 则 `ValueError`
- 若 `u["input_tokens"]` 是 `None`,`int(None)` 抛 `TypeError`
- 若字段缺失 → fallback 0,正常工作

**当前 call site 模式**(5 处:`backend/core/rag/llm.py:273, :285, :298, :308` 在 `chat_with_fallback` + `:363` 在 `chat_with_fallback_stream`):
```python
content, usage = _post_chat(...)  # 或 _post_chat_stream 路径
if usage is not None:
    _log_token_usage(model, usage["input_tokens"], usage["output_tokens"])
# else: usage=None 时既不写 log 也不 fallback(因为 _post_chat 已成功返回 content)
```

**关键风险**:若 `usage` 字段是字符串 `"invalid"` 等畸形数据,`int(u.get(...))` 抛 `AttributeError`/`ValueError`/`TypeError`,从 `_post_chat` 抛出 → 走到外层 `except Exception`(`:275, :289, :300, :312` 等)→ 触发 fallback 路径 → **把一次成功的 LLM 调用误判为失败,触发 Tavily / Bing 配额消耗**。`_post_chat_stream` 的 usage chunk 解析在 `:167-172` 有相同的脆弱性。

**修正方案**:抽出 helper 到新模块 `E:/backend/core/cost_alert_guard.py`,在 `_post_chat` / `_post_chat_stream` 内调用,把异常吞掉返回 None(由调用方决定 fallback 语义)。

**API 签名**:
```python
# backend/core/cost_alert_guard.py

from typing import Any, Mapping, Optional

def safe_get_usage_tokens(usage: Any) -> Optional[Dict[str, int]]:
    """Defensive extraction of input_tokens/output_tokens from LLM usage payload.

    兼容 DashScope-style {input_tokens, output_tokens} 与
    OpenAI-style {prompt_tokens, completion_tokens} 两种字段命名。

    规则:
      - usage is None 或非 Mapping → 返回 None
      - 任一字段值是合法非负 int → 该字段取该值
      - 任一字段值是非 int / 负数 / 字符串数字 / None → 该字段取 0
      - 所有字段都缺失或全部无效 → 返回 None

    返回值仅在"至少有一个字段是有效整数"时为 dict;否则 None。
    调用方对 None 走"跳过 cost 记录但不触发 LLM fallback"分支。
    """
```

**容错矩阵**:

| usage 输入 | 行为 |
|---|---|
| `None` | 返回 `None` |
| `"invalid"`(str) | 返回 `None`(非 Mapping) |
| `{}` | 返回 `None`(所有字段都缺) |
| `{"input_tokens": 100}` | 返回 `{"input_tokens": 100, "output_tokens": 0}` |
| `{"prompt_tokens": "abc", "completion_tokens": 50}` | 返回 `{"input_tokens": 0, "output_tokens": 50}`(前者无效 → 0,后者有效) |
| `{"input_tokens": -5}` | 返回 `{"input_tokens": 0, "output_tokens": 0}`(负数无效 → 0;后者也缺 → 0;全无效 → None) |
| `{"input_tokens": "100"}` | 返回 `{"input_tokens": 100, "output_tokens": 0}`(`int("100")` OK) |
| `{"input_tokens": None}` | 返回 `{"input_tokens": 0, ...}`(None → 0) |
| `{"input_tokens": 1.5}` | 返回 `{"input_tokens": 0, ...}`(非 int → 0) |

**修改调用点**(`E:/backend/core/rag/llm.py`):

位置 1:`_post_chat` 第 102-109 行:
```python
# 旧
usage = parsed.get("usage")
if usage is not None:
    usage = {
        "input_tokens": int(usage.get("input_tokens", usage.get("prompt_tokens", 0))),
        "output_tokens": int(usage.get("output_tokens", usage.get("completion_tokens", 0))),
    }

# 新
from backend.core.cost_alert_guard import safe_get_usage_tokens  # 顶部
usage_raw = parsed.get("usage")
usage = safe_get_usage_tokens(usage_raw)  # 异常已吞,返回 None 或 dict
```

位置 2:`_post_chat_stream` 第 167-172 行:
```python
# 旧
if "usage" in chunk and chunk["usage"]:
    u = chunk["usage"]
    accumulated_usage = {
        "input_tokens": int(u.get("input_tokens", u.get("prompt_tokens", 0))),
        "output_tokens": int(u.get("output_tokens", u.get("completion_tokens", 0))),
    }

# 新

    accumulated_usage = safe_get_usage_tokens(chunk["usage"])
```

**返回值语义微调**(关键!):旧代码在 usage 存在但字段全缺时会返回 `{"input_tokens": 0, "output_tokens": 0}`(假成功);新代码返回 None(诚实)。需要同步修改 5 处 `_log_token_usage` 调用点:
- 当前 `:273, :285, :298, :308, :363` 已是 `if usage is not None: _log_token_usage(...)` 模式 → **保留**(语义已对,只是 `_post_chat` 现在保证 usage 在解析失败时返回 None 而不是抛异常)
- 这才是真正的"safe"语义:cost 记录不写,但不假阳性触发 Tavily/Bing

**5 处调用点保持不变**(已经是对的模式),只需确保 `_post_chat` / `_post_chat_stream` 返回 None 而不是抛异常:
```python

if usage is not None:
    _log_token_usage(model, usage["input_tokens"], usage["output_tokens"])
# else: 跳过 cost 记录;继续正常返回 content(不要 fallback!)
```

### 2.4 Item D · `validate_cost_alert_payload` 字段级校验

**当前问题**:`E:/backend/api/dashboard.py:199-216 _read_cost_alert()` 只检查 `isinstance(ca, dict)`,但不验证字段类型。若 `data/health_status.json` 因外部脚本错误或磁盘损坏导致:
```json
{"cost_alert": {"level": "3", "thresholds": null, "month_cost_usd": "1500.5"}}
```
则 `chat.py:140` `cost_alert.get("level", 0) >= 3` 会:
- `"3" >= 3` → Python 3 中 str 与 int 比较抛 `TypeError`(在 Python 3.x,不再隐式排序)
- `thresholds.get("block", 1500)` 在 `thresholds = None` 时抛 `AttributeError`

→ **聊天入口崩溃**,与 v1.3.0 设计目标("cost-alert 任何异常都不应阻塞 LLM")冲突。

**修正方案**:在 `_read_cost_alert()` 末尾调 `validate_cost_alert_payload(raw)` 替代直接 `return ca`,把所有字段级验证封装在新模块。

**API 签名**:
```python
# backend/core/cost_alert_guard.py

DEFAULT_COST_ALERT: Dict[str, Any] = {
    "level": 0,
    "today_yuan": 0.0,
    "month_yuan": 0.0,
    "month": "",
    "thresholds": {"warn": 500.0, "high": 1000.0, "block": 1500.0},
    "updated_at": "",
}

def validate_cost_alert_payload(raw: Optional[Dict[str, Any]]) -> Dict[str, Any]:
    """Field-level merge/validation of cost_alert payload.

    规则(每个字段独立降级到默认值,互不影响):
      - level: int 且 0 ≤ level ≤ 3 → 取该值;否则 → 0
      - today_yuan / month_yuan:数值(int/float)且 ≥ 0 → 取该值(转 float);否则 → 0.0
      - month / updated_at:字符串 → 原值;否则 → ""
      - thresholds: dict 且 warn/high/block 都是合法数值 → 取该值;
          任何字段非法或缺失 → 用 DEFAULT_COST_ALERT.thresholds 对应字段

    始终返回一个完整 dict(确保下游 chat.py / dashboard.py 调用字段不抛 KeyError)。
    """
```

**容错矩阵**:

| `raw` 输入 | 返回 |
|---|---|
| `None` | `DEFAULT_COST_ALERT` 拷贝 |
| `{}` | `DEFAULT_COST_ALERT` 拷贝 |
| `{"level": "3"}` | level=0(字符串无效)+ 其他默认 |
| `{"level": 99}` | level=0(超范围)+ 其他默认 |
| `{"level": 2, "thresholds": null}` | level=2 + thresholds 用默认 |
| `{"level": 2, "thresholds": {"warn": "abc"}}` | level=2 + thresholds.warn=500.0 + 其他默认 |
| `{"level": 2, "month_yuan": -5}` | level=2 + month_yuan=0.0 |
| `{"level": 2, "month": 12345}` | level=2 + month="" |
| `{"level": 2, "month": "2026-07"}` | level=2 + month="2026-07" |

**修改调用点**(`E:/backend/api/dashboard.py`):
```python
# 旧 (第 199-216 行)
def _read_cost_alert() -> Dict[str, Any]:
    try:
        ...
        ca = health.get("cost_alert")
        if not isinstance(ca, dict):
            return dict(_COST_ALERT_DEFAULT)
        return ca  # ← 直接返回未验证的 dict

# 新

def _read_cost_alert() -> Dict[str, Any]:
    try:
        ...
        ca = health.get("cost_alert")
        if not isinstance(ca, dict):
            return dict(_COST_ALERT_DEFAULT)
        return validate_cost_alert_payload(ca)  # ← 验证后返回
    except Exception:
        return dict(_COST_ALERT_DEFAULT)
```

**DEFAULT_COST_ALERT 与 _COST_ALERT_DEFAULT 关系**:`dashboard.py` 已有的 `_COST_ALERT_DEFAULT` 保留(向后兼容),`cost_alert_guard.py` 新增的 `DEFAULT_COST_ALERT` 是模块级常量供 `validate_cost_alert_payload` 内部使用;两处默认阈值必须完全一致(v1.3.1 锁版不动)。

### 3.2 防御层次总结

| 边界 | v1.3.0 行为 | v1.3.1 行为 |
|---|---|---|
| LLM 返回 usage 字段异常(`{"input_tokens": "abc"}`) | `int(...)` 抛 `AttributeError`/`ValueError` → 误触发 fallback 路径 | `safe_get_usage_tokens` 返回 None 或部分字段 → 跳过 cost log,正常返回 content |
| `health_status.json` 损坏(`level: "3"`) | `chat.py:140` `>= 3` 比较抛 `TypeError` → 聊天入口崩溃 | `validate_cost_alert_payload` 降级 level=0 → 不阻断 |
| `health_status.json` thresholds=null | `thresholds.get("block", 1500)` 抛 `AttributeError` → 聊天入口崩溃 | validate 降级 thresholds 用默认 → 不阻断 |
| `cost_log.jsonl` 50MB+ 不轮转 | 撑爆 U 盘 | Rotate-CostLog 归档 + 截断 |
| 月度统计用 `-like` 字符串前缀比较 | UTC 时区正确(巧合);未来若 ts 改本地时区会漏算 | `DateTimeOffset::Parse().ToUniversalTime()` 规范化,鲁棒 |

### 3.3 不变量边界

- 所有 helper 是纯函数(无副作用);失败模式 = 返回 None 或默认值
- C 的 `safe_get_usage_tokens` 修改不改变 LLM 调用本身;只在拿到 usage 后做防御
- D 的 `validate_cost_alert_payload` 修改不改变 `_read_cost_alert` 的 I/O 路径;只在拿到 dict 后做验证
- A 的 Rotate-CostLog 在 cost-alert.ps1 累加步骤之前执行;轮转失败不影响累加(累加读的是旧文件,仍正确)

### 4.3 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| `[System.IO.Compression.GzipStream]` 在 PowerShell 5.1 + .NET Framework 4.x 不可用 | 🟢 | .NET Framework 4.x 自带 GZipStream;PS 5.1 = .NET 4.5+;`scripts/backup.ps1:67` 已有 zip 写操作先例 |
| GZipStream 压缩大文件耗时 | 🟢 | 50MB 文件压缩 ~2-3s,人工触发脚本可接受;不阻塞任何运行时路径 |
| `safe_get_usage_tokens` 把"全部字段无效"返回 None 与 v1.3.0 行为不一致 | 🟡 | v1.3.0 是返回 `{0, 0}` 假成功;v1.3.1 返回 None 才是诚实。**已在 §2.3 同步修改 4 处调用点** 改为"None → 跳过 log,不 fallback" |
| `validate_cost_alert_payload` 默认值若与未来真实 schema 偏差大 | 🟢 | DEFAULT_COST_ALERT 与 v1.3.0 `_COST_ALERT_DEFAULT` 字段完全对齐(仅新增字段级 type 校验层) |
| 测试覆盖不到所有 corner case(API 返回极少见字段名) | 🟢 | 已覆盖 str/int/float/None/负数/缺失/部分缺失;若出现新 corner,`safe_get_usage_tokens` 的 `try/except` 兜底返回 None |
| 4 atomic commit 中任一 commit 单独 revert 后,后续 commit 调用未撤销的 helper 失败 | 🟡 | helper 函数集中在 `cost_alert_guard.py` 一个文件;revert 任一 commit 时,后续 commit 若引用此模块会因 import 失败而无法启动 — 需配套 revert 后续 commit。文档说明在 release commit message |
| `safe_get_usage_tokens` 在 streaming 路径的边界(usage chunk 格式差异) | 🟢 | OpenAI/DashScope streaming usage chunk 格式一致;helper 对两种字段名都覆盖 |

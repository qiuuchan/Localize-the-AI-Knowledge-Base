## 1. 背景与动机

2026-07-22 同事电脑(WIN11 全新,未装 Docker)双击 start.bat,CMD 闪一下就没了。**项目当时没有任何 start.bat 运行日志的留存**,无法事后取证判断是哪一步死掉。

| 现象 | 原因 |
|---|---|
| 闪退 | 同事电脑缺 Docker / WSL 2 / admin → `--quiet` 安装静默失败 |
| 无法诊断 | start.bat 写的 `> "%TEMP%\kb-ai-*.txt"` 在执行机的 `%LOCALAPPDATA%\Temp`,**用户取不到** |
| 没法给发盘人(postmortem)| U 盘上无任何 start.bat 痕迹可看 |

**本次填的洞**:start.bat 每次运行写一个 `E:\logs\start-YYYYMMDD-HHMMSS.log`,**用户只要把这一个文件发微信就能取证**。

## 3. start.bat 改动详解

### 3.1 日志初始化 block(行 27-45,新增 19 行)

```bat
REM ============================================================
REM v1.5.2 · 启动日志初始化(为同事电脑闪退取证用)
REM 路径:  E:\logs\start-YYYYMMDD-HHMMSS.log
REM 失败兜底:U 盘只读时静默跳过,不阻断启动流程
REM ============================================================
set "LOG_DIR=%~dp0logs"
if not exist "%LOG_DIR%" mkdir "%LOG_DIR%" >nul 2>&1
set "LOG_TIMESTAMP=%date:~0,4%%date:~5,2%%date:~8,2%-%time:~0,2%%time:~3,2%%time:~6,2%"
set "LOG_TIMESTAMP=%LOG_TIMESTAMP: =0%"
set "LOG_FILE=%LOG_DIR%\start-%LOG_TIMESTAMP%.log"
echo === KB-AI start.bat v1.5.2 启动日志 %date% %time% Win=%OS% === > "%LOG_FILE%" 2>nul
if not exist "%LOG_FILE%" (
    echo    [警告] 启动日志创建失败(可能 U 盘只读),不影响启动流程
) else (
    echo    启动日志: %LOG_FILE%
)

REM ----- v1.5.2:保留最近 20 个 start-*.log -----
for /f "skip=20 delims=" %%f in ('dir /b /o-d "%LOG_DIR%\start-*.log" 2^>nul') do del "%LOG_DIR%\%%f" >nul 2>&1
```

**关键决策**:
- 时间戳 `YYYYMMDD-HHMMSS` = `date:~0,4` + `date:~5,2` + `date:~8,2` + `time:~0,2` + `time:~3,2` + `time:~6,2`
- **小时位空格兜底**:`%time%` 在 `< 10` 点小时位为空格(` 9:15:32`),`%LOG_TIMESTAMP: =0%` 把空格替换为 `0` — 否则文件名带空格
- 创建用 `>` 覆盖,后续 `>>` 追加
- 失败兜底 = 单行 `[警告]`,**不**弹 `pause` — 日志失败不该堵住启动

### 3.2 echo 镜像(约 50 处替换)

每个 `echo` 行尾追加 `>> "%LOG_FILE%"`。**不动**:
- `> "%TEMP%\kb-ai-*.txt"` 这类显式重定向 — 绝不动,会污染 `%TEMP%` 路径
- `pause` / `exit /b`(无 echo 输出)
- `dir /b /o-d` 这类已用 `2>nul` 抑制的命令回显
- `for /f ... in ('type ...')` 这类内部探针

### 3.3 退出收尾(endlocal 之前 +1 行)

```bat
REM ----- v1.5.2:启动日志退出收尾(endlocal 之前,变量还有效) -----
echo === KB-AI start.bat 退出 (errorlevel=%errorlevel%) %date% %time% === >> "%LOG_FILE%" 2>nul
```

**关键**:`endlocal` 后变量失效,这行必须在 `endlocal` 前 — 否则 `%LOG_FILE%` / `%errorlevel%` 被清掉。

## 附录 C · 实施期 hotfix(2026-07-22 三次实跑后落地)

> **背景**:spec 锁定后实跑验证,发现 3 个真实问题,均在 v1.5.2 同一 release commit 里收口。

### C.1 · 中文 locale `%date%` 含 `周三` 污染文件名(severity 🟢)

**症状**:同事电脑实跑后日志文件名变成 `start-周三022607-235424.log`(无效字符 + 可读性差)。

**根因**:中文 Win11 默认 `reg query` 下,`%date%` 输出是 `周三 2026/07/22`,而 spec 设计的切片公式 `date:~0,4`-`date:~5,2`-`date:~8,2` 切到了 day-of-week。

**修复**(`start.bat` 行 33-39):

```bat
REM 用 wmic os get localdatetime 拿到纯数字时间戳(20260722235549),
REM 避开 %date% 在中文 locale 含 "周三" 这种 day-of-week,文件名更干净
for /f "tokens=2 delims==" %%i in ('wmic os get localdatetime /value 2^>nul') do set "LOG_TIMESTAMP=%%i"
if not defined LOG_TIMESTAMP (
    REM 兜底:某些精简系统无 wmic → 用 %date% %time% 拼
    set "LOG_TIMESTAMP=%date:~0,4%%date:~5,2%%date:~8,2%%time:~0,2%%time:~3,2%%time:~6,2%"
    set "LOG_TIMESTAMP=%LOG_TIMESTAMP: =0%"
)
set "LOG_FILE=%LOG_DIR%\start-%LOG_TIMESTAMP:~0,8%-%LOG_TIMESTAMP:~8,6%.log"
```

**结果**:文件名变成规范的 `start-20260722-235754.log`(纯数字 + 1 个 hyphen,无中文无 timezone 后缀)。

### C.2 · `wmic` 输出 `.244000+480` 后缀污染文件名(severity 🟢)

**症状**:第一次 wmic 测试时文件名变成 `start-20260722235549.244000+480.log`(centiseconds + timezone offset)。

**修复**:加切 `LOG_TIMESTAMP:~0,8%-%LOG_TIMESTAMP:~8,6%` — 只取前 8 位日期 + 后 6 位时间,丢掉 nanoseconds 和 timezone offset。

**结果**:`start-20260722-235754.log` ← 完美。

### C.3 · 🔴 **关键**:CMD IF 块内 ASCII `()` 在 echo 内容里触发 `was unexpected at this time`(syntax error)

**症状**:第一次实跑只写了 1 行 banner 就停了,bash 报错 `... was unexpected at this time`。

**根因**:CMD 的 IF 块解析器**会计数 `echo` 内容里的 ASCII `(` 和 `)`**(即使在引号内),把 `(约 1 分钟)` 误当成 IF 块的子块边界。原 v1.5.1 start.bat 这些括号在 echo 里没问题(无 `>>` 行为差异),但加上 `>> "%LOG_FILE%"` 重定向后,CMD 严格计数,语法炸。**Microsoft 已知 bug**(Stack Overflow 多个回答)。

**修复**(覆盖 6 处 IF 块内 echo,典型形态):

| 原 | 改后 |
|---|---|
| `echo    Docker 未安装,正在从 U 盘离线包自动安装(约 1 分钟)... >> "%LOG_FILE%"` | `echo    Docker 未安装,正在从 U 盘离线包自动安装 · 约 1 分钟... >> "%LOG_FILE%"` |
| `echo [错误] Docker Desktop 启动超时(90 秒),请检查:` | `echo [错误] Docker Desktop 启动超时 · 90 秒,请检查:` |
| `echo    1. 电脑是否已重启?(首次安装 Docker 需要重启一次)` | `echo    1. 电脑是否已重启? 首次安装 Docker 需要重启一次` |
| `echo    2. WSL 2 是否已启用?(控制面板 → 程序 → ...)` | `echo    2. WSL 2 是否已启用? 控制面板 → 程序 → ...` |
| `echo    [警告] 模型复制失败(robocopy 返回 !errorlevel!),...` | `echo    [警告] 模型复制失败 · robocopy 返回 !errorlevel! · ...` |
| `echo    [跳过] PDF/PPTX 解析服务(本批 USB 未打包);...` | `echo    [跳过] PDF/PPTX 解析服务 · 本批 USB 未打包 · ...` |
| init block 的 `[警告] 启动日志创建失败(可能 U 盘只读),不影响启动流程` | 同样改用 `·` separator |

**回归测试覆盖**(`test_no_ascii_parens_in_if_block_echo`):6 个可疑字符串白名单,任一在 start.bat 内重新出现 → CI 红。

**结果**:二次实跑 → 走完 8/8 → 49 行日志 → exit summary 写出,errorlevel=125(由 docker compose 残留,不阻断日志)。

## 7. 风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 用户二次启动同秒 → 文件名 collision | 🟢 | 时间戳 HHMMSS 够秒级精度 |
| `>> "%LOG_FILE%"` 漏一处 | 🟢 | `test_echo_lines_redirect_to_log` ≥ 80% 守门 |
| U 盘只读 → 启动流程卡住 | 🟡 | `2>nul` + `if not exist` 兜底 |
| 日志被同事打开中→写失败 | 🟢 | 单行 echo,不会"中断"流程 |
| stop.bat 没同步 | 🟡 | 已锁定 scope = stop.bat 留待 v1.5.3 |
| 老同事 / 老 U 盘 没有 logs/ 目录 | 🟢 | `mkdir >nul 2>&1` 自动创建 |

## 3. 数据模型与迁移

10 项里仅 #1 / #8 触及 schema;其他为 API/前端/参数。

### 3.1 新表 — `tags` + `doc_tags`

```sql
-- 标签定义:作用域 = database(跨 db 同名允许)
CREATE TABLE IF NOT EXISTS tags (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  database_id TEXT    NOT NULL,                    -- 与 databases.id 对齐(default / <user_db>)
  name        TEXT    NOT NULL,                    -- UI 展示名(同 db 内唯一)
  color       TEXT    NOT NULL DEFAULT '#FF540E',  -- XAIAgent 主色
  created_at  TEXT    NOT NULL,
  UNIQUE(database_id, name)
);

-- 文档-标签多对多
CREATE TABLE IF NOT EXISTS doc_tags (
  source      TEXT    NOT NULL,    -- 命名空间形式 <db_id>::<filename>
  tag_id      INTEGER NOT NULL,
  created_at  TEXT    NOT NULL,
  PRIMARY KEY (source, tag_id),
  FOREIGN KEY (tag_id) REFERENCES tags(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_doc_tags_tag ON doc_tags(tag_id);
```

**作用域决策**:db 作用域。理由:用户场景是"分公司文档分类",分公司天然分库;跨库同名标签易引发认知混淆。

### 3.2 新字段 — `sessions.history_limit`

```sql
-- 启动自检阶段执行,try/except 捕 duplicate column
ALTER TABLE sessions ADD COLUMN history_limit INTEGER NOT NULL DEFAULT 50;
```

- 旧 sessions:无值时取默认 50
- chat 调用:取最近 `history_limit` 条历史喂 LLM
- UI 反馈:超过 80% 时提示"接近上限"

### 3.3 不改 schema — 级联删除 #9

保留 `DELETE /api/knowledge/databases/{id}?cascade=true` 形态,改 default + UI:

- 默认 `cascade=false`(安全)
- 若 db 还有子文档 → 返回 `409 {child_documents: N, requires_cascade: true}`;前端弹模态"确认级联删除 N 个文档及对应 Qdrant collection?"
- 确认后调 `?cascade=true`,串行清理:`tags` / `doc_tags`(按 database_id) → `processing_state` → `keyword_index`(按 source 前缀) → Qdrant `delete_collection(kb_chunks_<db_id>)`
- 错误处理:Qdrant 不可达 → 写 degradation_events(component='Vector') + 返回 200 但带 `warning`

### 3.4 不改 schema — bulk_assign Qdrant payload #11

`bulk_assign_documents_to_database(doc_ids, target_db)` 新增 Qdrant 同步步骤:

- 旧 source:`<old_db>::<filename>` → 新 source:`<target_db>::<filename>`
- 走 Qdrant client `set_payload` 批量更新,带 `wait=true`(批量 ≤ 100 条/批)
- keyword_index.source 同步更新(原有逻辑保留)
- 失败降级:Qdrant 不可达 → 写 degradation_events(component='Vector', message='payload rewrite partial') + 返回 200 + `warning`
- 涉及文件:`backend/core/sqlite.py`(或新 `backend/core/bulk_assign.py`)

### 3.5 迁移策略

- **不引入新迁移框架**:复用 v0.8.11 启动自检模式
- `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ... ADD COLUMN` try/except 捕 duplicate column
- **无数据回填**:tags/history_limit 都是新功能,旧数据取默认即可
- bulk_assign Qdrant payload 仅在用户主动调迁移 API 时触发
- 迁移时机:`boot.py` 第 7 阶段(orphan_recovery 之后)加一个 `schema_migration` 步骤

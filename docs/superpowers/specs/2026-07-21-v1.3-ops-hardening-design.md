### 2.4 Item 4 · `scripts/cost-alert.ps1` 月度配额告警

**新建** `E:/scripts/cost-alert.ps1`(PS 5.1 兼容)。

**职责**:
1. 从 `data/cost_log.jsonl` 累加每日 LLM 调用 token(input/output 分别计费)
2. 按 `.env` 中 `COST_ALERT_THRESHOLDS`(可选,默认值 `warn=$500 / high=$1000 / block=$1500`)解析告警等级
3. 等级 ≥ 1 写入 `data/health_status.json` 的 `cost_alert.level` + `cost_alert.today_yuan` + `cost_alert.month_yuan`
4. Dashboard **始终**渲染 cost-alert 卡片(level=0 时显示"本月用量 ¥X / ¥Y"+ 进度条);level ≥ 2 时卡片顶部加橙色告警条 + 文字提示
5. 等级 ≥ 3 时 `chat.py` 入口检查 → **SSE 200 + `error` event**(在 retrieve 之前 yield,不抛 HTTPException)

**v1.3.0 契约决定(SSE 200 + error event)**:`/api/chat` 在 cost_alert.level ≥ 3 时返回 **HTTP 200**(SSE 连接保持打开),在 SSE 流中 yield `event: error, data: {reason: "monthly_cost_exceeded", ...}` 通知前端。**不**抛 HTTPException(503),因 EventSourceResponse 已启动后无法再抛 HTTPException。原 spec §2.4 写"HTTP 503"是 spec ↔ 实现 不一致,v1.3.0 release 接受 SSE 200 契约;前端应监听 `event: error` 而非依赖 HTTP 状态码判定 cost-alert 阻断。

**阻断分支细节**(chat.py 入口):
```python
# 在 retrieve 之前 yield error event(避免无谓的 Qdrant + keyword 查询)
if cost_alert.level >= 3:
    save_degradation_event(component="LLM", detail=f"cost-alert block: ¥{month_yuan:.0f}")
    yield {
        "event": "error",
        "data": json.dumps({
            "reason": "monthly_cost_exceeded",
            "month_yuan": month_yuan,
            "threshold": thresholds["block"],
            "hint": "知识库检索仍可用,降级到 websearch"
        }, ensure_ascii=False),
    }
    return
```
- **首次启动从未跑过 cost-alert.ps1**:`health_status.json` 不存在或 `cost_alert` 字段缺失 → 默认 `level=0`,**不阻断**
- **降级时检索仍可用**:SSE error event 后,前端可捕获并显示"AI 暂不可用,知识库检索仍可用";KnowledgePage / 文档浏览不依赖 `/api/chat` 路径

**数据采集**(配套改动):
- `backend/core/rag/llm.py` 在 `chat()` / `chat_stream_with_fallback()` 末尾加 `_log_token_usage(model, in, out)` hook
- 借 v0.8.11 `atomic_io.atomic_append_jsonl` 写入 `data/cost_log.jsonl`,单行格式:**`{ts: ISO8601, model: str, in: int_tokens, out: int_tokens}`**(`cost_yuan` **不在 log 时算**,由 rollup 时按当时单价表计算 — 单一真相源)
- **`streaming` 模式**:在 `body` 加 `stream_options={"include_usage": True}`;循环结束后从最后一段 delta 中提取 `usage` 字段(`llm.py:105 _post_chat_stream` 配合 `extract_streaming_content`)
- **`non-streaming` 模式**:从 `response["usage"]` 直接取
- 任一模式提取失败 → 跳过该次记录,不抛异常

**月度切换**:
- 月度 = **UTC 自然月**(每月 1 日 00:00:00 UTC 起算;不按本地月以避免 timezone 漂移)
- rollup 时按日志 `ts` ISO8601 解析归属月
- 回溯范围:本年初起回溯全量(`cost_log.jsonl` 体积增长,设 50MB 滚动阈值,超限归档为 `cost_log.jsonl.YYYY-MM.gz`)

**单价表**(硬编码于脚本顶部,文档标注"以阿里云百炼 2026-07 公示价为准;**实施时核对官方定价**"):

| 模型 | input ¥/MTok | output ¥/MTok |
|---|---|---|
| qwen3.6-plus | 4 | 12 |
| qwen3.7-max | 12 | 36 |
| text-embedding-v3 | 0.7 | n/a |

**阈值依据**:
- `warn=$500` ≈ 中等用量 ¥512/月(PRD §3.4.3)的 97%,轻度超即提醒
- `high=$1000` ≈ 中等的 1.95x,重度用量红线
- `block=$1500` ≈ 中等的 2.93x,只阻止超额用户(用户可调 `.env`)

- **手动**:`pwsh -File scripts/cost-alert.ps1`
- **自动**:手动运行;`stop.bat` / `start.bat` 不修改(§1.3 不变量);后续若用户授权可改 start.bat 调一次

```
backend/api/chat /api/chat SSE
  ↓
[chat.py 入口:cost_alert.level >= 3 ? early-return 503 : 继续]
  ↓
backend/core/rag/llm.py  阿里云百炼 API 调用
  ↓
response.usage = {input_tokens, output_tokens, model}
  ↓
_log_token_usage(model, in, out)   ← 新增 hook,纯函数
  ↓
atomic_append_jsonl
  ↓
data/cost_log.jsonl  ← 单行:{ts, model, in, out}   ← cost_yuan 不写,rollup 现算
  ↓
(scripts/cost-alert.ps1 手动触发)
  ↓
累加当日 cost(按 UTC 月)+ 比对 COST_ALERT_THRESHOLDS
  ↓
data/health_status.json  cost_alert: {level, today_yuan, month_yuan}
  ↓
GET /api/dashboard/overview (v1.1.0 已实现,需补 cost_alert 字段)
  ↓
backend/api/dashboard.py _read_cost_alert() → health_status.json 解析
  ↓
_build_overview() 追加 cost_alert 字段
  ↓
DashboardPage 渲染 cost-alert 卡片 (level=0 / >=2 不同 UI)
```

**Block 路径**:`chat.py` 入口加 `if cost_alert.level >= 3: raise HTTPException(503)`(在 retrieve 之前 early-return,省一次 query)。

**降级路径**:LLM 不可用时,`run-checks.ps1` / `health_status.json` 仍正常,知识库检索仍可用,符合 v1.0.0 degradation-guide §3。

### 4.3 风险与缓解

| 风险 | 缓解 |
|---|---|
| PRD 改动偏离用户决策(误改 §2 风险表) | spec 阶段反复确认"保留 §1 / §2 / §5 历史不动";实施时逐段 git diff review |
| pre-commit 误伤非 ruff 文件 | `ruff check` 显式限定 `backend/ tests/` 两个目录;不扫 scripts/ 顶层 .ps1 与 scripts/hooks/ bash;不递归根 `*.md` |
| cost-alert 阻断 LLM 时用户被困 | health_status.json 暴露阻断状态;Dashboard 卡片 + degradation-guide.md 加 1 条新场景;503 在 retrieve 之前 early-return,省一次 query |
| 钩子脚本在 WSL/MinGW 路径不一 | 用 `$PSScriptRoot` 相对路径,不依赖绝对;文档注明"Git for Windows 自带 bash" |
| `pwsh` 不在 PATH → pre-push 静默失效 | `scripts/install-hooks.ps1` 加 `Get-Command pwsh` 探测;pre-push hook 内 `which pwsh` 失败时 echo 警告 + exit 0(降级可推送);文档注明 Windows 默认 `powershell.exe` (5.1) 不等于 `pwsh` (7+) |
| 单价表过时 | 文档标注"以阿里云百炼 2026-07 公示价为准,实施时核对官方定价,变化时手动改 cost-alert.ps1 顶部常量" |
| 月度切换 timezone 漂移 | 显式用 UTC 自然月(每月 1 日 00:00:00 UTC 起算);不按本地月 |
| `cost_log.jsonl` 体积增长 | 50MB 滚动阈值,超限归档为 `cost_log.jsonl.YYYY-MM.gz` |
| 月度切换起算日回溯 | 本年初起回溯全量;归档文件不丢 |
| dashboard.py 字段新增破坏前端 | `cost_alert` 为可选字段,缺失时前端降级显示"用量数据采集中" |
